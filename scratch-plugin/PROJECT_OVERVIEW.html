核心概念直觉（用类比一次看懂）

本质 · 类比 · 反向回忆线 · 为什么
① 文件即真相，DB 是目录卡
会话文件是唯一真相；数据库只是"目录卡"——记归属和进度，可随时从原件重建
类比书店：目录卡丢了，书架上的书还在；反过来书丢了，目录卡写什么都没用
反向回忆：目录卡 → DB 派生索引；书架上的书 → 会话文件。启示：索引允许短暂不准，定期盘点（对账）对齐。
② 增量 + md5 = 只抄新页
追加式文件"新内容永远在末尾"；用"上次抄到的位置"当书签，只抄新长的部分
类比手账：只往后写，抄过的位置做标记，下次只抄标记之后的新页
反向回忆：手账标记 → fileSize；验旧页没改 → md5 前缀；验不过整本重抄 → 全量回退。
③ 对账 = 定期盘点
文件系统 + DB 无法原子，不追求"文件变了数据库立刻变"，定期扫描对齐
类比仓库盘点：清点货架（文件）→ 更新账本（DB）→ 账实不符就修正
启示：对象存储（S3 桶清单）、事件溯源（日志→投影）的标准做法。
④ Token 不进浏览器 = 管家保管钥匙
凭证由 Host 进程保管（credentials 文件 + 内存）；浏览器只见身份
类比管家：管家替你保管家门钥匙，前台（浏览器）只知道"你住这"
为什么：钥匙进前台 = 谁都能翻（devtools / 历史 / localStorage）。
⑤ SSO Ticket = 电影票
机器身份 → 浏览器身份用"一次性短命凭证"桥接（30 秒、消费即删）
类比电影票：一次性、30 秒作废，捡到也进不了下一场
对比：直接传 token = 把家门钥匙贴在门上（7 天有效）。
⑥ 三层隔离 = 门卫 → 楼层门禁 → 房间钥匙
认证（你是谁）→ 存储约束（这层楼你进不去）→ 接口校验（这间房你没钥匙）
类比写字楼：门卫查证件（Bearer）→ 电梯楼层门禁（DB 归属约束）→ 房间钥匙（接口校验）
启示：防御纵深，不是单一检查点。
⑦ 幂等自愈 = 错了就整本重印
任何对不上 → 全量重传，替换天然幂等
类比复印：错了不用"擦掉重写"，直接整本重印——结果一定正确
启示：正确性靠"验证 + 幂等 + 可重建"，不靠状态永远精确。
⑧ 每次拉标记 = 每次问坐标
client 本地不记"同步到哪了"，每次同步前问 server 要坐标（fileSize+md5）
类比导航：不靠记忆认路，每次出发前重新定位
为什么：本地内存崩溃即丢、压缩会重写文件；server 标记是唯一权威。

决策对比总表（为什么不用 X）

面试官最爱问对立面——这是弹药库
决策选 Y为什么不用 X代价/注意
会话存储文件真相 + DB 派生索引不用"DB blob 为真相"：文件是官方格式，可重放/版本化索引漂移 → 对账兜底
同步粒度字节增量 + md5不用整文件：O(n²) 带宽需前缀校验保证安全
进度标记md5（内容精确）不用 size+mtime：漏判压缩重写需读文件算哈希
位置来源每次拉 server 标记不用本地记：崩溃即丢、压缩弄脏每次多一次 GET
会话凭证Redis 服务端会话不用 JWT：撤销要黑名单需 Redis 可用
两套认证Bearer + Cookie 分治不合并：暴露 token 或嗅探调用方多维护一套
跨边界凭证30 秒一次性 code不用 token 直传：泄露窗口 7 天 vs 30 秒多一跳往返
一致性写路径尽力 + 对账不用事务强一致：文件系统 + DB 无法原子短暂漂移可接受
并发控制每会话单飞锁不用消息队列：单一写入者，锁就够最坏 409 → 全量
密码存储scrypt（计划）当前明文是 MVP 取舍后置，已识别风险
真密钥server 内 resolve不下发给员工机器网关唯一出口

技术亮点 · 讲法手册

一句话 + 怎么说 + 追问
1

文件即真相，DB 是派生索引

怎么说："会话原始日志（官方 DSH 格式）作为真相存文件，PG 只存归属和同步标记——标记能从文件重算。文件系统和数据库没法原子，所以写路径尽力同步 + 对账兜底，这是对象存储和事件溯源的通用模式。"
追问：索引漂移怎么办？→ 对账：启动自动 + 后台手动。
2

md5 校验的字节增量

怎么说："文件是追加式的，新内容永远在末尾。client 每次先拉 server 的标记（位置+指纹），本地算前缀 md5 验证没被重写，一致就只传新增字节；server 收到再用 baseMd5 校验。整个系统没有游标、没有 seq 连续性校验——复杂度从'状态对齐'降级为'内容验证'。"
追问：为什么是 md5 不是 size+mtime？→ 内容级精确；内容指纹非秘密，无盐。
3

幂等自愈

怎么说："全量上传是原子替换（tmp + rename），重复传同样的内容结果不变。断网、重启、并发、版本不匹配——每个异常路径都收敛到正确状态。"
追问：并发两次同步？→ 每会话单飞锁 + server 409 兜底。
4

Token 永不进浏览器

怎么说："登录时服务器返回的 token 被本地 Host 拦截保存，浏览器只收到用户信息。token 不会出现在 devtools、浏览器历史、localStorage——泄露面最小。重启后 Host 用持久化 token 水合恢复。"
追问：为什么要这样？→ token 进浏览器 = 钥匙放前台。
5

SSO 短命 code 桥接

怎么说："员工点'进后台'，Host 拿 token 换一次性 code，浏览器带 code 跳服务器消费，服务器种 Cookie。code 只能换一个新会话、30 秒过期、消费即删——泄露窗口从 7 天缩到 30 秒，OAuth2 authorization code 同款。"
追问：为什么不直接传 token？→ 长命凭证过浏览器边界 = 钥匙贴门上。
6

模型网关凭证代换

怎么说："本地 DSH 用公司 token 调网关，服务器校验身份后换成真 DeepSeek key 转发。员工机器上没有任何真实 API key——即使整台机器被盗也拿不到模型凭证。"
追问：流式体验？→ 无缓冲转发，客户端零感知。
7

隔离靠数据库约束，不靠信任

怎么说："会话归属用 DB 约束保证：ON CONFLICT DO UPDATE WHERE user_id 匹配——会话已被别人绑定，你的写入直接失败。查询层按 userId 过滤，接口层再校验，三层纵深。"
追问：隔离在哪几层？→ 存储（约束）→ 查询（过滤）→ 接口（鉴权）。
8

fail-closed 版本门控

怎么说："上传时校验 header.version 与 SESSION_FORMAT_VERSION，不一致返回 415。新格式客户端不会写坏老服务器，升级是明确的 fail-closed。"
追问：升级怎么办？→ 两端一起升级，格式由 DSH 单方面拥有。

三版迭代 + 九个关键坑

Session 同步三版迭代

v1 增量事件 + seq 游标 + 连续性校验游标跨根失效、压缩 seq 空洞被拒、无限 gap 刷屏、崩溃窗口重复追加

v2 整文件上传简单正确，但 O(n²) 带宽
↓
v3 md5 校验的字节增量（最终）内容验证取代状态机

六个关键踩坑

坑教训
PowerShell ANSI 读 UTF-8，中文注释吞换行 → env 加载失败配置避免非 ASCII 注释；脚本显式 -Encoding UTF8

概念层（能推出机制吗）

1. 为什么"文件变了数据库不用立刻变"？
提示：手账 / 目录卡
文件系统 + 数据库无法原子事务；数据库只是可重建的派生索引，允许短暂漂移，靠对账定期对齐——最终一致 + 例行收敛的通用模式。
2. 增量同步的"书签"是什么？什么情况下书签会失效？
提示：位置 + 指纹
书签 = fileSize（上次抄到的字节位置）+ contentMd5（前缀指纹）。失效场景：文件被压缩重写 → 前缀 md5 不一致 → 全量重传重建书签。
3. 为什么 ticket 比 token 安全？类比是什么？
提示：电影票
ticket 一次性 + 30 秒过期 + 消费即删，泄露即废；token 是 7 天长命凭证。泄露窗口从 7 天缩到 30 秒。

机制层（能讲清流程吗）

4. 一次同步的五个步骤是什么？每步防什么？
① 拉标记（知道 server 存到哪）② 本地算 md5（内容指纹）③ 决策（跳过/增量/全量）④ 上传（server 校验 base + size）⑤ 更新标记。防：重复传输、错误追加、标记失真。
5. token 在哪些地方出现、哪些地方绝不出现？
出现：server Redis、client credentials 文件、client 内存、HTTP 头（Host→server）。绝不出现：浏览器 JS、localStorage、URL、浏览器历史。
6. 三层隔离分别在哪层、用什么机制？
存储层：DB 归属约束（ON CONFLICT WHERE user_id 匹配）→ 查询层：userId 过滤 → 接口层：Bearer→userId→归属校验（403/404）。

决策层（能回答"为什么不用 X"吗）

7. 为什么不用 JWT / 整文件上传 / size+mtime？
JWT：无状态但撤销要黑名单；Redis 会话可撤销可续期 O(1)。整文件：O(n²) 带宽。size+mtime：漏判压缩重写，md5 内容级精确。
8. 为什么两套认证不合并？合并会怎样？
合并 = 要么浏览器拿到 token（暴露）、要么 server 嗅探调用方（脆弱）。机器要可携带 Bearer、浏览器要自动 Cookie，交付方式不同。

陷阱层（能说出坑吗）

9. 换根后为什么同步会"全跳过"？怎么修？
PG 标记指向旧根文件，client 拉到的 md5 与本地一致 → 跳过 → 新根永远空。修：对账（清标记/删行）强制全量重建，或换根时重置标记。
10. 为什么一个坏文件能拖垮整个分析端点？防御是什么？
sessionController.list() 读到坏文件（首帧非 header）直接抛错 → 端点 400 空响应。防御：端点容错降级 + 对账清理 + 全量上传后 inspect 首帧校验防未来损坏。
11. 图片请求在网关里怎么走？模型由谁决定？
client files-first：POST /files（multipart raw 透传，不解析）→ 拿 file-id → chat 引用。模型由 client 选择器决定，请求体带 model，网关原样透传不覆盖——client 与 server 模型配置各自独立，两边都是 DSH 所以模型名一致。
12. 无头会话文件怎么被拦住？拒绝后状态如何一致？
全量上传后 server inspect 校验首帧（必须恰好一行 session header）；失败 → 删文件 + 清 PG 标记 + 400。client 读文件时复检大小，半写状态跳过本轮——从源头避免发出损坏内容。

面试问答

高频追问与回答
为什么文件是真相，数据库只是索引？

会话文件是官方持久化格式，可重放、版本化；PG 的标记可从文件重算。文件系统 + 数据库无法原子，所以「写路径尽力 + 对账收敛」——对象存储/事件溯源通用模式。

为什么用 md5 不用 size+mtime？

size+mtime 可能漏判「同大小同 mtime 内容变了」（压缩重写）。md5 内容级精确。注意：这里是内容指纹不是秘密，不加盐；加盐是密码哈希概念，且会破坏对账重算比对。

增量同步怎么保证不损坏？

三重校验：① client 增量前 md5 证明前缀一致；② server 用 baseSize+baseMd5 与自身标记比对；③ 追加后 stat 校验大小 == totalSize。任何失败 → 409 → 全量替换（幂等）。

为什么 token 不进浏览器？两套认证为什么不合并？

token 进浏览器 = 暴露在 devtools/历史/localStorage。合并 = 浏览器拿 token（违反底线）或嗅探调用方（脆弱）。机器要 Bearer、浏览器要 Cookie，交付方式不同。

为什么网关要代理 Files API？模型谁决定？

client 的 llm-deepseek 默认 files-first（上传→file-id→chat 引用）。网关只代理 chat 会让 /files 404 → 每次降级 base64（可用但费带宽、大图受限）。代理 /files（multipart raw 透传）后，client 走网关与直连 DeepSeek 行为完全一致；上传失败仍自动降级 base64 兜底。模型由 client 选择器决定、请求体透传——网关只换 key，不替 client 选模型。

为什么用 SSO ticket 而不是直接传 token？

长命 token 跨边界泄露窗口 7 天；30 秒一次性 code 泄露即废、用途单一、消费即删——OAuth2 authorization code 标准做法。

数据隔离落实在哪几层？

三层：存储（DB 归属约束，跨用户改写不可能）→ 查询（userId 过滤）→ 接口（Bearer→userId→归属校验，403/404 区分）。

为什么不用 JWT？

Redis 会话可服务端撤销、可滑动续期、O(1) 校验；JWT 无状态但撤销要黑名单，复杂度转移。

100 人并发的性能怎么保证？

提交边界触发（低频）+ 每批 O(增量) + 每会话单飞锁；server 每批 = Redis 鉴权 + 两次 PG + 追加写盘。早期"每次全量解码"有 O(n²) 问题，改游标缓存后消除。

已知的取舍/风险？

密码明文、token 未哈希、禁用不即时生效——都识别了，按 MVP 后置。演进方向：scrypt、token sha256、网关校验 status、双 token（受官方适配器 401 重试限制）。
