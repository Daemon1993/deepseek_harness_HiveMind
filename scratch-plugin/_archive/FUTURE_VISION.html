HiveMind 是一个本地优先的团队 AI Agent 协作与知识沉淀平台。
员工各自用自己的本地 DSH 干活，一台中心 Server 统一持有模型凭证、归档过程、治理访问——不把 Agent 搬上云，也不牺牲本地能力与数据主权。

N 本地 DSH · 1 Server DSH 过程 + 产物 绑定归档 凭证不出 Server 文件即真相 LLM 可直接读会话原生格式

架构拓扑

工具/工作区/Git 在本地执行；Server 只做认证、模型网关、会话归档——永不执行 Agent。

01

它在回答什么问题

当每个员工都开始用 AI Agent 干活——写代码、改文件、跑命令——企业怎么管？HiveMind 给的不是"搬上云"那个答案。

怎么让一群本地 AI Agent，认得出谁、只让看自己的、真密钥不出 Server，
同时把过程沉淀成团队可复用的知识？

🔑

凭证集中

真 DeepSeek key 只在中心 Server。模型请求经网关代换后流式转发，员工机器碰不到密钥。

💻

工作本地

工具、shell、文件、Git 全在员工机器执行。Server 永不执行 Agent，不跑员工工具。

📥

过程归档

每个会话的字节副本 + Git 活动单向流向 Server，沉淀成团队的"工作档案"。

02

四个价值取向

几版演进里始终一致的设计取向——这才是架构的骨架，不是功能清单。

P1

数据主权在本地

会话原生文件先落员工机器，Server 只是副本。文件即真相，PG 是派生索引。靠"验证 + 幂等 + 可重建"，不追求强一致。

P2

单向数据流

只本地 → Server，不做双向。归档与分析不需要回灌，砍掉了同步冲突这一整层复杂度。

P3

隔离靠约束不靠信任

DB 归属约束 + 接口鉴权三层。跨用户操作在存储层被拒，不是靠客户端自觉。

P4

可观测但隐私收敛

用 gitRemote 取代本地路径、analytics 只存元数据。只沉淀安全的管理信号，不含消息/命令/文件内容。

03

关键差异化

LLM 知识沉淀最吃"过程 + 产物"绑定的数据。这是 HiveMind 的喂料口优势。

代码平台
GitHub
✕ 有产物，无过程
✓ commit / diff
✕ 看不到协作怎么发生
对话平台
AI Chat
✓ 有过程，无产物
✓ prompt / 工具
✕ 不绑定代码改动
HiveMind
过程 + 产物
✓ session 全量过程
✓ git 变更绑定
✓ 谁在哪个仓库怎么协作的
LLM 可直接读原生会话格式
04

未来能实现的效果

底座把过程与产物归档到位后，上层接 LLM 分析即可沉淀——这正是为它准备的喂料口。

🧑

个人维度

📊

个人工作画像

聚合一个人所有 session + Git 活动：碰过哪些项目、什么工具链、典型工作流、反复踩的坑、成长曲线。过程数据越积越多，沉淀价值非线性增长。

🔄

AI 协作习惯复盘

哪些 prompt 模式有效、哪些工具调用总失败、哪类任务烧 token 最多、低效在哪。让"怎么用 AI"本身变成可优化的技能。

📚

个人经验库

把解决过的难题沉淀成"我是怎么用 AI 解这个的"，可检索、可复用。下次遇到同类问题，先查自己的经验而非从零开始。

🗂️

项目维度

🧠

项目记忆

按 gitRemote 聚合一个仓库下所有人的协作：仓库约定、架构决策是怎么在 session 里被讨论、落地成 commit 的。让项目有"自己的记忆"。

🚀

新人 Onboarding

聚合历史 session 生成"这个项目踩过的坑、典型解法路径、约定在哪里"。新人遇到问题时先检索团队经验，而不是反复问人。

🔗

跨人经验流动

A 解决过的同类问题，B 再遇到时能检索到 A 的协作过程——不只看最终 commit，而是看到"这条改动是怎么被想出来的"。

📈

改动质量洞察

把 commit 的 stat 和背后的 AI 协作关联：哪类改动一次过、哪类总返工、哪类任务 token 效率低。团队级的质量与效率仪表。

🔍

过程回溯

任意一次代码改动，能回放"它背后的 AI 对话、工具调用、决策路径"。代码审查不再只看 diff，而看懂来龙去脉。

🎯

团队画像

谁擅长哪类任务、哪个模块的知识集中在谁身上、团队的能力分布与协作网络。组织级洞察，不只是个人。

05

演进路径

分阶段建设——底座是喂料投资，不是白修。上层落地的那一刻，归档的数据开始产出价值。

阶段 01 · 当前已建

底座层：通道 + 治理 + 可观测

认证隔离、模型网关、会话字节归档、Git 元数据、对账、管理台基础分析。这条链路已打通并经过事务化与重试打磨。

凭证不出 Server 三层隔离 MD5 字节增量同步 事务化发布 失败自愈重试 对账兜底
阶段 02 · 未来接通

知识层：LLM 分析沉淀

在已有底座上接 LLM 分析 agent，读取 session 原生格式 + Git 变更，产出个人画像、项目记忆、经验检索。会话副本是 DSH 原生格式，LLM 直接可读，无需另起一套。

个人工作画像 项目记忆 跨人经验检索 改动质量洞察 过程回放
接通的关键两步

从"归档"到"沉淀"只差两个字段

① 把现在只存的代码变更 stat 升级为可取 diff 内容（git-sync 现刻意只传元数据）。
② 把 会话内容检索面 暴露给分析 agent。这两步一通，LLM 沉淀直接落在已有底座上。

结论

底座是为上层喂料准备的，不是过度工程。纯 GitHub 只有产物没过程，纯对话平台只有过程没产物——HiveMind 把两者绑定，这正是 LLM 知识沉淀天然落点。对个人、对项目，过程数据越积越多，沉淀价值非线性增长。这不是"先修好管道等水来"，而是管道本就为水而修。
