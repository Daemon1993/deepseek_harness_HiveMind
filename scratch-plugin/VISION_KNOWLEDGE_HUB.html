北极星：企业 AI 知识中枢

所有员工在 AI 上做过的"目标 → 过程 → 结果"，沉淀成可搜索、可复用、可决策的公司知识

一句话愿景

公司内部用 AI 做过的每一件事（会话过程、代码产出、工具用法）都被记录下来，提炼成"经验卡"，统一索引——以后任何人有任何需求，先问平台："公司里谁做过类似的？哪些项目适合？怎么实现？" 平台自动检索、分析、给出带引用的建议。

✅ 可行③ 检索层（统一搜索）向量 + 全文 + 元数据过滤（项目/用户/时间/权限）

这是"企业 AI 知识中枢"的最小骨架。② 是命门——没有经验卡，③④ 搜的是原始命令，搜出来也不能总结，愿景永远是 PPT。

逐层详解

每层要做什么 · 可行性 · 产出物

① 采集层（已完成）

数据内容状态
Session 日志用户消息（含图片/多模态，经 Files API 代理 files-first 归档）、工具调用、模型对话、token、时间线（本地完整归档 + 服务器副本）✅ 完成
Git 操作操作流水（谁/哪会话/哪项目/动作/成败）✅ Step 1
代码变更commit hash + 文件数 + 增删行（幂等）✅ Step 1
diff 内容层（远期）文件路径列表 + 摘要（不存 diff 内容）📋 规划

② 提炼层（命门——下一步要做）

把原始记录变成"可搜索的语义"，LLM 提炼：

输入（已有数据）:
  首条用户消息      → 目标："解决登录偶发超时"
  工具调用序列      → 过程："定位 xxx → 改 yyy → 跑测试"
  git 提交 + 最终回复 → 结果："提交 zzz，问题解决"

输出（一次 LLM 调用）:
  会话经验卡: 目标 / 过程 / 结果 / 可复用提示词 / 关联提交

会话经验卡

每个会话一页：目标-过程-结果-提示词——经验的最小单元

两周可出 demo

项目能力画像

从项目历史会话+提交提取：解决过什么问题、技术栈、常用工具

与经验卡同层

提交摘要

commit 的一行语义摘要（diff-tree 数据 + message）

轻量

③ 检索层（统一搜索）

能力技术回答的问题
语义检索embedding + 向量库（pgvector）"哪个项目解决过类似问题"
关键词检索全文索引（命令、工具名、路径、commit）"谁改过这个文件/跑过这个命令"
元数据过滤项目 / 用户 / 时间 / 角色权限"A 项目的历史我能搜吗"
重排混合检索 + rerank"哪个结果最相关"

④ 问答/决策层（你描述的场景）

输入: "要在项目 X 做一个需求 Y，怎么做？"

流程:
  ① 检索: 全公司有没有人做过类似的事（跨项目经验卡）
  ② 分析: 项目 X 的历史画像（擅长什么、技术栈、活跃度）
  ③ 生成: 复用方案 + 相关提交/会话链接 + 可行性 + 风险 + 建议

约束: 强制引用来源 · 坏答案检测 · 权限隔离

⚠️ 可行，但质量是三层叠加的命门：检索差→找不到对的；摘要差→找到也没用；LLM 推理差→建议不靠谱。

阶段 1 的"会话经验卡"是整个愿景的立锥之地——它证明"原始记录 → 可复用知识"成立，之后的一切都建立在它之上。

三个硬前提（不做就翻车）

数据量 · 权限 · 质量

① 数据要积累够

愿景价值 = 数据量 × 数据质量。采集三个月和三天是两个系统——短期看不到价值是正常且必然的

采集即价值

② 权限模型要提前设计

跨项目检索会把 A 项目内容暴露给 B 项目的人——角色/项目隔离"谁能搜到哪个项目"，不能后面补

提前设计

③ 摘要质量要有护栏

经验卡提炼质量决定一切；坏经验进库比没有经验更危险（会误导别人）

需人评估

6

风险与诚实评估

这个愿景最容易被证伪的三个地方
摘要质量不可控怎么办？

LLM 提炼的质量是命门。对策：摘要生成后人工抽样评估（建立质量标准）；检索结果带原文引用（用户可核）；坏经验标记/下架机制。

隐私边界——跨项目检索会不会泄露？

会话内容可能含敏感信息。对策：① 经验卡在本地 DSH 提炼（内容不出员工机器，只上传摘要）；② 服务器端检索按项目/角色隔离；③ 敏感项目可标记为"不外搜"。

做了没人用怎么办？

这是内部工具的通病。对策：不做"系统"，做"答案"——先手动/半自动地回答几个真实问题（"我们 AI 花了多少"、"哪个项目适合做 X"），证明价值再扩；种子用户是技术负责人/架构师。

价值密度——大多数记录是低价值的？

诚实说：不是每条会话都值得沉淀。对策：提炼时做价值过滤（只有"目标明确 + 有产出 + 有可复用点"的会话才生成经验卡），宁缺毋滥——坏经验进库比没有更危险。
