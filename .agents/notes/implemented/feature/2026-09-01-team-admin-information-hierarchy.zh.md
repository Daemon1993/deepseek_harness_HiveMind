# Agent Note: Team 管理后台信息层级

Status: implemented

[English](2026-09-01-team-admin-information-hierarchy.md) | 中文

## Problem

团队管理后台已经展示账号、Session、项目、Git 和模型数据，但导航、卡片、表格与装饰渐变的视觉权重接近，运行状态不易快速浏览。

## Decision

管理端 Client 使用统一、克制的企业控制台视觉系统：浅色常驻导航、包含当前栏目和 Server 状态的白色页头、中性的内容区域、以蓝色表示主要操作，并统一卡片与表格的边框和间距。现有路由、数据字段、权限与操作流程保持不变。

仅管理员可见的 DSH 工作台菜单只会在 Server 本机浏览器中打开本地 `/team/workspace` 入口。入口会再次要求管理员会话，用其换取 DSH 浏览器令牌；局域网代理会拒绝该路径。

每日工作事实会在 Asia/Shanghai 17:20 根据用户已持久化的 Session 分析与 Git 摘要提炼。仅 Server 持有的 LLM 返回经过校验的结构化字段；每次重算会覆盖同一“用户＋本地日期”的记录，后续报表可聚合这些事实而无需重新读取原始会话日志。

用户页使用同一个工作日期查询生成状态、查看详情并手动重算。全员手动重算会立即返回并作为 Server 后台任务继续执行，同时提供可查询的任务状态，使页面切换后无需保持原请求也能恢复“生成中”提示。

PostgreSQL 缺少 `users.json` 中的默认账号时逐个恢复。已有账号资料和密码仍是权威数据，种子不会覆盖它们。

## Alternatives considered

**保留装饰性渐变主题。** 该方案继续制造视觉噪声，使不同重要程度的指标看起来同等突出。

**替换整个管理应用。** 新应用会重复已经可用的分析、账号、同步和详情流程，却不会改善数据接口。

## Consequences

后台更易浏览，并保留现有后端行为。管理页增加了一组自有样式，后续面板需要遵循相同的导航、内容区域和状态表达规范。缺失的种子用户恢复时不带密码，除非管理员明确设置。
